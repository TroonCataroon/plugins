# MouseMux UI Setup

## Target configuration

Use the seat plan in `config/seat-plan.json`.

### Troon seat

- Type: physical
- Cursor color: cyan
- Assign the primary physical mouse
- Assign the primary physical keyboard
- Do not window-lock this seat

### Agent seat

- Type: virtual Input Mapper user
- Cursor color: magenta
- No physical devices assigned
- Window lock required before live actuation

### Cursor seat

- Optional
- Cursor color: green
- Leave unassigned until there is a defined second-user workflow

## Setup sequence

1. Install and open MouseMux.
2. Select **Switched mode** for the first configuration.
3. Enable **Multi Keyboard**.
4. Identify each physical mouse and keyboard using the inventory generated by `Discover-InputDevices.ps1`.
5. Assign the primary physical devices to the Troon seat.
6. Create the Agent virtual user for Input Mapper.
7. Set the Agent cursor to magenta.
8. Run `Start-AgentSandbox.ps1`.
9. In MouseMux, lock the Agent virtual user to the generated Notepad window.
10. Move the physical mouse and verify the cyan cursor remains independent.
11. Open Input Mapper.
12. Enable MCP, but keep **Arm MCP** off.
13. Copy the exact endpoint displayed by Input Mapper.
14. Configure Codex with `Configure-MouseMuxMcp.ps1`.
15. Restart the MCP client and complete `ACCEPTANCE-TEST.md`.

## Do not proceed when

- A physical mouse or keyboard is assigned to the wrong seat.
- The virtual cursor can leave the sandbox window.
- The MCP endpoint is not loopback port `41760`.
- **Arm MCP** turns on automatically.
- The fallback shortcut stops an unrelated process.
- `Verify-MultiMouseControl.ps1` reports a critical failure.
